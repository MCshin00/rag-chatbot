# 평가 기준과 채택 조건

정식 실행 전에 커밋하고, 결과를 본 뒤에는 바꾸지 않는다. 문항 작성 기준은 [authoring.md](authoring.md)에 있다.

## 비교하는 것

같은 질문 30개로 두 청킹 전략을 비교한다. 검색 결과 상위 5개를 생성 모델에 넘기는 조건에서의 비교이며, "어떤 청킹이 일반적으로 낫다"를 보이는 실험이 아니다.

| | 조문 단위 (`article`) | 고정 크기 (`fixed`) |
|---|---|---|
| 자르는 방법 | 조문 하나가 조각 하나 | 법령별로 본칙 조문을 줄바꿈으로 이어 붙인 뒤 400자 창을 350자씩 옮기며 자름(겹침 50자) |
| 조각 수 | 132(삭제 조문 2개 제외) | 약 156 |
| 걸친 조문 | 하나 | 조각마다 겹치는 조문 목록과 원문 위치를 기록 |

두 방식에서 같게 고정하는 것: 문항, 질문 임베딩(한 번 만들어 재사용), 임베딩 모델과 검색 방식(아래 "검색 설정 선택"으로 정한다), 코사인 거리의 정확 검색(근사 인덱스 없음), k=5, 생성 모델 `gpt-5.4-mini-2026-03-17`, `reasoning.effort=none`, 프롬프트 버전, 최대 출력 토큰, 구조화 출력 스키마, 재시도 0.

## 검색 지표

**주 지표: 근거 충족.** 답 있는 문항마다, 실제로 생성에 넘긴 상위 5개 조각의 원문 범위를 합친 것이 근거 묶음 하나의 구절을 모두 덮으면 **완전 충족**, 일부 구절만 덮으면 **일부 충족**, 하나도 못 덮으면 **미충족**이다.
- 구절 위치는 법령·조·항까지 확인한다. 다른 조문에 같은 문구가 있어도 인정하지 않는다.
- 검색되지 않은 중간 부분을 원문에서 가져와 메우지 않는다. 겹친 부분은 한 번만 센다.
- 이 지표는 "사전에 주석한 구절이 들어왔는가"를 잰다. 그 구절로 답이 충분한지는 사람이 판정한다.

**보조 지표: 조 단위 Recall@1/3/5.** 근거 묶음마다 (묶음의 조문 중 상위 k개 조각이 걸친 조문의 비율)을 구하고, 묶음 중 가장 높은 값을 쓴다.

답 없는 문항은 검색 지표의 분모에서 뺀다.

## 답변 판정

| 판정 | 기준 |
|---|---|
| 맞음 | `must_include`를 모두 말하고, `must_not`에 해당하는 말이 없고, 인용한 조각이 근거 묶음 하나를 모두 덮는다 |
| 부분 | `must_not`은 없지만, `must_include` 일부가 빠졌거나 인용이 근거를 다 덮지 못한다 |
| 틀림 | `must_not`에 해당하는 말이 있거나, 핵심 주장이 조문과 다르거나, 근거 없이 단정한다 |
| 잘못된 보류 | 답 있는 문항에서 답하지 않았다 |
| 적절한 보류 | 답 없는 문항에서 "이 문서로는 확인할 수 없다"고 했다. 이유를 덧붙이는 것은 괜찮지만 보호 여부를 단정하면 틀림이다 |

- 답 없는 문항은 응답 상태(답/보류)와 관계없이 **내용으로** 판정한다. 판단 기준을 설명하면서 "이 문서로는 확인할 수 없다"고 하고 단정하지 않으면, 모델이 보류로 표시하지 않았어도 적절한 보류다.
- **완전 정답**은 답 있는 문항의 "맞음"과 답 없는 문항의 "적절한 보류"다.
- **근거 없는 단정**은 "틀림" 중에서 문서에 없는 내용을 사실처럼 말한 경우다. 따로 센다.
- 인용 적합성(인용한 조각이 근거 묶음을 덮는가)은 자동으로 계산해 판정표에 미리 적고, 판정하는 사람이 확인한다.

판정 예문 (D01: 정기예금 8천만 원 + 적금 4천만 원, 한 은행)

| 답변 | 판정 | 이유 |
|---|---|---|
| 같은 은행의 예금은 합쳐서 1억 원까지 보호돼요. 1억 2천만 원 중 1억 원까지예요. [법 제32조, 시행령 제18조 인용] | 맞음 | 합산, 한도, 결론을 모두 말하고 근거를 인용 |
| 1억 원까지 보호돼요. [시행령 제18조만 인용] | 부분 | 합산 설명이 없고 법 제32조 인용이 빠짐 |
| 예금과 적금이 각각 1억 원까지라 전액 보호돼요. | 틀림 | `must_not`(각각 1억 원) |
| 이 문서에서 찾지 못했어요. | 잘못된 보류 | 답 있는 문항 |

## 보류 원인

최종 응답이 보류이면 원인을 하나 기록한다.

| 원인 | 뜻 |
|---|---|
| 검색 미충족 | 근거가 충족되지 않은 상태에서 모델이 보류 |
| 생성 보류 | 근거가 충족됐는데 모델이 보류 |
| 검사 차단 | 모델은 답했지만, 인용이 비었거나 검색 결과에 없는 ID를 인용해 검사 노드가 보류로 바꿈 |
| 실행 오류 | API 오류, 응답 중단, 구조화 출력 파싱 실패. **보류로 세지 않고** 실행 실패로 따로 센다 |

검사 노드는 **존재하지 않는 인용을 차단**할 뿐이다. 인용이 답을 뒷받침하는지는 확인하지 않는다.

## 채택 조건

기본값은 **조문 단위**다. 고정 크기는 개발 20문항에서 아래를 모두 만족할 때만 채택한다.

1. 완전 정답이 조문 단위보다 **2개 이상** 많다. (2는 통계적 유의성이 아니라, 문항 하나가 5%p인 규모에서 정한 실무 기준이다.)
2. 조문 단위에서 완전 정답이던 문항이 고정 크기에서 완전 정답이 아니게 된 경우(회귀)가 **이번 단일 실행에서 관측되지 않는다**.
3. 조문 단위에 없던 근거 없는 단정이 고정 크기에서 **새로 생기지 않는다**.

문항별 개선·회귀·동률 목록은 채택 여부와 관계없이 남긴다. 부분 정답에 점수를 따로 주지 않는다.

## 확인셋

개발셋으로 결정하고 모델·프롬프트·설정을 동결한 뒤, 확인 10문항을 두 방식으로 한 번씩 실행한다. 확인 결과로 방식을 다시 고르거나 설정을 고치지 않는다.

보고하는 것은 **완전 정답 차이의 방향**이다.
- 개발셋과 같은 방향: "소규모 확인셋에서도 같은 방향을 관찰했다"
- 반대 방향: "개발셋의 차이가 재현되지 않았다"
- 동률: "확인셋에서는 차이를 관찰하지 못했다"

근거 충족과 근거 없는 단정은 따로 보고한다. 금액·보호 범위·핵심 조건에 관한 중대한 오류가 나오면, 선택한 방식의 품질이 충분하다는 주장은 하지 않는다.

## 하지 않는 것과 한계

- 문항·방식마다 한 번만 실행한다. 생성 변동성은 측정하지 않는다. 회귀가 난 문항만 다시 돌리지 않는다.
- 자동 재시도는 하지 않는다(SDK, LangChain, 출력 복구 모두).
- 정답과 판정은 AI 두 개와 사용자가 확인한 것이고, 법률 전문가 검증이 아니다.
- 답 없는 문항은 개발 4개, 확인 2개뿐이다. 보류 능력은 이 사례에서 관찰한 결과로만 말한다.

## 검색 설정 선택 (설정 고정 전)

처음 설정(`text-embedding-3-small`, 벡터 검색만)으로 동작 확인 5문항을 돌리자 답 있는 4문항에서 조문 단위는 완전 충족 0·일부 1, 고정 크기는 0·0이었다. 모델은 엉뚱한 조각을 받고 보류했다. 저장된 벡터와 검색 계산에는 오류가 없었고(질문 재임베딩 유사도 1.0, 조문 조각의 최근접 고정 조각 122/132가 같은 조문), 법령 문구를 그대로 넣은 질문("보험금의 지급한도는 1억원")도 그 문구가 든 조각을 찾지 못했다. 기록: `eval/runs/20261024-2000*-smoke-*`, `eval/runs/probe-*.json`.

그래서 조각 방식 비교 전에 검색 설정을 아래 규칙으로 하나 고른다. 고른 설정은 두 방식에 똑같이 쓴다.

- 후보(단순한 순서): ① small + 벡터 ② large + 벡터 ③ small + 하이브리드 ④ large + 하이브리드. large는 `text-embedding-3-large`(3,072차원).
- 하이브리드: 벡터 상위 20개와 BM25 상위 20개를 RRF(상수 60)로 합쳐 상위 5개. BM25는 낱말마다 두 글자씩 자른 바이그램을 단어로 쓴다.
- 평가: 답 있는 개발 16문항 × 두 방식의 **검색만** 돌린다(생성 호출 없음). 확인용 문항은 쓰지 않는다.
- 규칙: 완전 충족 개수의 두 방식 합(32건 만점)이 가장 많은 후보. 같으면 Recall@5 평균이 높은 쪽, 그것도 같으면 앞 순서(더 단순한 쪽).
- 기록: `scripts/select_retrieval.py`가 `eval/runs/retrieval-select-*.json`에 문항별 결과와 선택을 남긴다.
- 고른 뒤 동작 확인 5문항을 다시 돌리고 설정을 동결한다. 이 선택은 개발 문항으로 한 튜닝이라, 정식 실행의 개발셋 성적은 이 튜닝을 포함한 값이다. 확인셋은 이 튜닝과 무관하다.

## 동작 확인과 동결

- 정식 실행 전에 개발 문항 5개로 동작을 확인한다(확인셋은 쓰지 않는다). 이때 프롬프트와 설정을 고칠 수 있다.
- 동작 확인이 끝나면 프롬프트 버전과 설정을 동결하고 정식 실행을 시작한다.
- 모델은 동작 확인 단계에서 접근·호환 문제가 있을 때만 `gpt-6-luna`로 바꿀 수 있다. 정식 실행 뒤에는 성적을 보고 바꾸지 않는다.
