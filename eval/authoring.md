# 평가 문항 작성 기준

개발용 문항과 확인용 문항이 같이 따르는 기준이다. 검색·생성 방식(청킹, 프롬프트, 모델)과 무관하게 쓴다. 문항을 쓰는 사람은 검색 결과나 개발 성적을 보지 않는다.

## 사용자와 문서

- 묻는 사람: 금융회사에 돈을 맡긴 개인이나 법인. "내 돈이 보호되는가, 얼마까지, 어떤 조건에서"가 중심이다.
- 문서: `data/processed/act_20260102.jsonl`(예금자보호법, 2026. 1. 2. 시행본)과 `data/processed/decree_20250901.jsonl`(시행령, 2025. 9. 1. 시행본)의 **본칙**. 부칙은 없다. 삭제된 조문(법 제19조, 제38조의2)은 근거로 쓰지 않는다.
- 답은 이 두 문서의 본문만으로 판단한다. 예금보험공사 안내문, 상식, 다른 법률로 보충하지 않는다.

## 쓰는 순서

1. **사용자 상황부터 쓴다.** 누가 어떤 상황에서 무엇을 결정하려는지 한 줄로 적는다. 조문 제목이나 문구를 의문문으로 바꾸는 방식으로 시작하지 않는다.
2. 질문은 그 사람이 실제로 쓸 말로 쓴다.
   - 법령 용어(부보금융회사, 보험사고, 예금등, 지급결정 등)를 쓰지 않는다. 일반인이 실제로 쓰는 말(예금자보호, 보험금, IRP 등)은 쓴다.
   - 상황은 답에 필요한 사실만 쓴다. 답과 관계없는 부연 설명("이 보험은 ~와 관계없다")을 넣지 않는다.
3. 그다음 조문을 찾아 답할 수 있는지 정한다.
4. 검색이 어려워 보인다는 이유로 문항을 빼거나 쉽게 고치지 않는다.

## 유형과 개수

| 유형 | 뜻 | 개발 20 | 확인 10 |
|---|---|---:|---:|
| 한도·합산 | 얼마까지 보호되나, 여러 예금을 어떻게 합치나 | 4 | 1 |
| 보호 대상 | 어떤 금융회사·상품·권리가 보호되나 | 3 | 2 |
| 조건·계산 | 대출 상계, 가지급금, 이자 계산 등 조건에 따라 달라지는 것 | 3 | 2 |
| 복수 근거 | 법률과 시행령, 또는 두 개 이상의 조문을 함께 봐야 답할 수 있는 것 | 4 | 1 |
| 절차·기관 | 보험금 지급·청구 절차, 공사의 역할 등 예금자에게 필요한 절차 | 2 | 2 |
| 답 없음(범위 밖) | 이 문서가 다루지 않는 것(예: 특정 상품의 금리, 다른 법률로 보호되는 기관) | 2 | 1 |
| 답 없음(정보 부족) | 관련 조문은 있지만 질문에 필요한 구체적 정보가 문서에 없는 것 | 2 | 1 |

- 문항 하나는 한 유형만 갖는다. 여러 유형에 걸치면 가장 어려운 쪽으로 적는다.
- 시행일·개정 시점을 묻는 문항은 쓰지 않는다(부칙이 없고 시행일은 메타데이터라 판정이 모호하다).
- 후속 질문(앞 대화가 필요한 질문)은 쓰지 않는다. 모든 문항은 한 번에 묻는다.

## 문항 형식

`eval/*.jsonl`에 한 줄에 문항 하나를 JSON으로 쓴다.

```json
{
  "id": "D01",
  "group": "limit-sum-1",
  "type": "한도·합산",
  "situation": "한 은행에 정기예금과 적금을 나눠 넣은 직장인",
  "question": "한 은행에 정기예금 8천만 원, 적금 4천만 원이 있어요. 은행이 망하면 얼마까지 돌려받나요?",
  "answerable": true,
  "evidence_sets": [
    [
      {"doc_id": "act", "article": "32", "paragraph": 1, "quote": "각 예금자등의 예금등 채권의 합계액에서"},
      {"doc_id": "decree", "article": "18", "paragraph": 7, "quote": "보험금의 지급한도는 1억원"}
    ]
  ],
  "must_include": ["같은 금융회사의 예금은 합쳐서 본다", "한도는 1억 원이다", "1억 원까지 보호된다"],
  "must_not": ["예금마다 각각 1억 원", "5천만 원까지", "1억 2천만 원 전액"],
  "notes": ""
}
```

| 필드 | 규칙 |
|---|---|
| `id` | 개발은 `D01`~`D20`, 확인은 `H01`~`H10` |
| `group` | 핵심 사실과 추론이 같은 문항끼리 같은 값. 금액만 바꾸거나 같은 내용을 바꿔 말한 문항은 같은 묶음이다. 같은 조문을 쓴다는 이유만으로 묶지 않는다 |
| `answerable` | 문서 본문만으로 답할 수 있으면 `true` |
| `evidence_sets` | 답에 필요한 근거 **묶음**의 목록. 묶음 하나 안의 구절은 **모두** 있어야 한다. 같은 주장을 다른 조문으로도 뒷받침할 수 있으면 묶음을 하나 더 쓴다(대체 근거). 답 없음 문항은 `[]` |
| `quote` | 해당 조·항 본문에서 **그대로 복사한** 구절. 주체, 적용 조건, 결론, 질문에 관련된 단서·예외를 빠짐없이 덮도록 필요한 만큼 여러 개 쓴다. 너무 짧게(예: "1억원"만) 쓰지 않고, 항 전체를 통째로 쓰지도 않는다. 도입부("다음 각 호의…")가 뜻에 필요하면 도입부도 따로 넣는다 |
| `paragraph` | 항 번호. 항 번호가 없는 조문은 `null` |
| `must_include` | 맞는 답이 반드시 말해야 하는 주장. 짧은 평서문으로, 결론을 바로 쓴다("1억 원까지 보호된다"). "~인 것은 아니다", "~라고 볼 수는 없다" 같은 돌려 말하기와 유보 표현을 쓰지 않는다. 틀린 답은 `must_not`에 쓴다 |
| `must_not` | 하면 틀리는 단정. 답 없음 문항에는 "근거 없이 보호된다/안 된다고 단정" 같은 것을 적는다 |
| `notes` | 판정할 때 필요한 해석 메모. 없으면 빈 문자열 |

## 답 없음 문항

- 적절한 답은 "이 문서로는 확인할 수 없다"는 보류다. 근거 없이 "보호되지 않는다"고 단정하면 틀린 답이다.
- 정보 부족형은 관련 조문이 검색될 만한 질문이어야 한다. 예: 보호 대상 금융회사는 문서에 있지만, 특정 회사 이름이 그 대상인지는 문서에 없다.

## 검사

작성한 파일은 아래 명령으로 형식과 인용을 검사한다. 모든 `quote`가 해당 조·항 본문에 그대로 있는지, 원문 HTML의 해당 조문에도 있는지 확인한다.

```bash
uv run python scripts/validate_questions.py eval/<파일>.jsonl
```
