# 예금자보호 법령 RAG 챗봇

예금자보호법과 시행령을 근거로 예금자보호 질문에 답하는 챗봇이다. 답에는 근거 조문을 붙이고, 법령에서 근거를 찾지 못하면 지어내지 않고 답을 보류한다.

LangGraph, pgvector, FastAPI를 쓴다.

## 문제 정의

### 누가 무엇을 묻나

금융회사에 돈을 맡긴 개인과 법인이 묻는다. "내 돈이 보호되는가, 얼마까지, 어떤 조건에서"가 중심이다.

- **한도:** 한 은행에 예금 1억 5천만 원이 있으면 얼마까지 돌려받나?
- **대상:** 확정기여형 퇴직연금도 보호되나?
- **조건:** 같은 은행에 대출이 있으면 보험금을 어떻게 계산하나?
- **여러 조문:** 연금저축과 일반 예금은 한도를 따로 적용하나? (법률 제32조와 시행령 제18조를 함께 봐야 한다)
- **후속 질문:** 앞 질문 뒤에 "그럼 연금저축은?"
- **답 없음:** 법령에 근거가 없는 질문. 예를 들어 특정 상품의 금리

법령의 표현과 질문의 표현은 다르다. 질문은 "적금 두 개"라고 하지만 조문은 "예금등 채권의 합계액"이라고 쓴다. 또 "외화예금"처럼 안내문에는 있어도 조문에는 그 단어가 없는 경우도 있다.

### 문서 범위

| 문서 | 기준 | 출처 |
|---|---|---|
| 예금자보호법 | 2026. 1. 2. 시행본 (법률 제21065호) | [국가법령정보센터](https://www.law.go.kr/법령/예금자보호법) |
| 예금자보호법 시행령 | 2025. 9. 1. 시행본 (대통령령 제35687호) | [국가법령정보센터](https://www.law.go.kr/법령/예금자보호법시행령) |

- 기준일은 2026-10-19이고, 그날의 현행본을 쓴다.
- 본칙만 넣는다. 부칙(경과 규정, 시행일)은 넣지 않는다.

법령을 고른 이유:

- **원문을 공개할 수 있다.** 법령은 저작권 보호 대상이 아니다(저작권법 제7조). 반면 예금보험공사 안내 페이지는 무단 복제와 배포를 금지한다. 그래서 이 저장소에는 원문을 함께 둔다.
- **조·항·호 구조가 분명하다.** 조항 단위로 자르고, 조항 단위로 정답을 붙일 수 있다.
- **실제 개정 이력이 있다.** 시행령 제18조 ⑦항의 보험금 지급한도는 2025. 9. 1. 5천만 원에서 1억 원으로 바뀌었다. 개정 전후로 색인을 바꿔 답이 따라 바뀌는지 확인할 수 있다.

### 하지 않는 것

- 개인 사안에 대한 법률 판단. 답은 조문 안내이고 법률 자문이 아니다.
- 법령에 없는 내용의 추측. 근거가 없으면 보류한다.
- 다른 법률로 보호되는 곳. 새마을금고(새마을금고법), 신용협동조합(신용협동조합법), 우체국 예금 등은 이 문서 범위 밖이다.
- 예금보험공사 안내문, 보도자료, FAQ. 이용 조건 때문에 넣지 않는다.

### 성공 기준

평가 문항은 30개다. 개발용 20개로 고쳐 가며 보고, 확인용 10개는 마지막에 한 번만 평가한다.

| 지표 | 뜻 |
|---|---|
| Recall@k | 정답 조문(법령, 조, 항)이 검색 상위 k개에 들어온 비율 |
| 정답률 | 답이 조문 내용과 맞는 비율. 직접 판정한다 |
| 보류 | 답이 없는 문항에서 지어내지 않고 보류한 비율 |
| 인용 적합성 | 붙인 출처가 실제로 답을 뒷받침하는 비율 |
| 질문당 비용과 시간 | 토큰, 비용, 검색 시간, 생성 시간 |

## 실행

[uv](https://docs.astral.sh/uv/)가 필요하다.

```bash
uv sync
uv run python scripts/fetch_laws.py   # data/sources.json의 법령 HTML을 data/raw/로 받는다
uv run python scripts/parse_laws.py   # 조문 단위 JSONL을 data/processed/로 만든다
```

## 데이터

- `data/sources.json`: 수집할 법령과 시행일
- `data/raw/`: 국가법령정보센터 본문 HTML
- `data/processed/`: 조문 하나가 한 줄인 JSONL. 필드는 법령, 조 번호, 제목, 장·절, 본문, 항 목록, 개정 이력이다
